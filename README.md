# FORMULA — аналитика магазина

Интерактивный дашборд Ozon по согласованному макету: светлые карточки, оранжевый акцент, Manrope и выборочное полужирное начертание.

## Запуск

Требуется Node.js 24 (проверено на 24.19.0).

```sh
npm ci
npm run dev
```

Рабочий каталог — корень этого репозитория. Vite запускается на порту 5173. Для проверки production-сборки:

```sh
npm run build
npm run preview
```

## Что работает

- Разделы «Обзор», «Товары», «Воронка» и «Качество».
- Четыре главные KPI-карточки только в «Обзоре»; в остальных разделах — их собственные блоки.
- Календарь варианта 03: два месяца, выбор/предпросмотр диапазона, быстрые периоды 7/14/28/90 дней, даты вне отчёта недоступны. На мобильном месяцы расположены друг под другом.
- Кнопки «Сегодня»/«Вчера» привязаны к МСК; быстрые интервалы считаются от последнего дня отчёта. Изменения применяются только по кнопке, отмена сохраняет предыдущий диапазон.
- Все выпадающие списки — собственные меню в стиле дашборда, с выбором мышью и клавиатурой; системные select/date-меню не используются.
- Общий поиск по названию, артикулу и SKU; фильтры ABC и наличия FBO/FBS в строке.
- Карточки KPI переключают выбранный показатель, график и таблицу товаров. Оранжевым выделен активный показатель.
- Общий период применяется одновременно к карточкам, графику и таблице; отдельного скрытого ограничения графика последними 7 днями нет.
- Средняя цена на графике за неделю/месяц считается как сумма заказов / число товаров в этой неделе/месяце, а не среднее дневных цен.
- Автомасштаб: до 31 дня — дни, до 180 — недели, далее месяцы. Группировку можно выбрать вручную.
- В разделе качества показаны итоги и доли отмен/возвратов. Переключатели статусов меняют серии графика и товары в таблице. При дневном отображении более 31 дня используются линии; ось количества имеет только целочисленные отметки.
- Пересчёт показателей, спидометр выкупа, воронка и анализ концентрации суммы заказов.
- График: дни, календарные недели (с понедельника), месяцы; линия или столбцы; подсказки при наведении.
- Сравнение с предыдущим периодом той же длины, если весь период есть в файле.
- Сортировка, страницы таблицы, карточка товара с собственным графиком.
- Импорт ежедневного отчёта Excel `.xlsx` с листом «По товарам» в Web Worker.
- Выгрузка выбранных товаров в CSV с защитой от выполнения формул.
- Адаптивный интерфейс, доступные подписи элементов, управление диалогами клавиатурой.

## Данные и методика

Исходный файл: `analytics_report_daily_2026-10-30_10_17.xlsx`, магазин FORMULA, период 30.07–29.10.2026. Подготовленный набор содержит 18 047 строк и 311 SKU и находится в `public/data/report.json.gz`.

Без фильтров за полный период KPI берутся из строки «Итого и среднее». При фильтрации — из соответствующих строк детализации. Таблицы и графики всегда используют детализацию. В исходном файле есть расхождения:

| Показатель        | Итоговая строка | Сумма детализации |
| ----------------- | --------------: | ----------------: |
| Сумма заказов     |     8 151 692 ₽ |       8 151 738 ₽ |
| Выкуплено товаров |           2 141 |             2 169 |

Дашборд раскрывает это в окне «О данных и расчётах», не корректируя исходные строки. Средняя цена считается как сумма заказов / заказанные товары. Величины «Заказано товаров» и «Выкуплено» — количество единиц, а не число отдельных заказов.

ABC используется из отчёта, а не рассчитывается заново. FBO и FBS могут одновременно присутствовать в строке: выбор схемы не распределяет продажи между ними. Остатки, рейтинги и отзывы по дням не суммируются. Отношения этапов воронки описывают суммарные события, а не уникальных покупателей; эти отношения могут превышать 100% и отличаться от конверсий Ozon.

Выкуп, отмены и возвраты привязаны к дате заказа по методике исходной выгрузки; поздние статусы могут измениться в следующем отчёте. Сумма заказов включает отмены и возвраты и не является прибылью.

## Импорт Excel

Кнопка «Загрузить Excel» обрабатывает файл локально, без отправки на сервер, и заменяет набор данных в текущей вкладке. После обновления страницы возвращается встроенный исходный отчёт. Поддерживается ежедневная структура Ozon «По товарам», до 30 МБ. `.xls`, произвольные таблицы и другие типы отчётов не поддерживаются. Нестандартные стили Excel игнорируются, данные извлекаются из XML.

Чтобы заменить исходный набор для последующих запусков:

```sh
node scripts/prepare-data.js /path/to/report.xlsx
```

Это обновит `public/data/report.json.gz`. Затем повторите проверки и сборку. Исходный Excel для работы приложения не нужен.

## Проверки

```sh
npm test
npm run test:e2e
npm run build
```

`npm test` проверяет реальные суммы из исходного набора, фильтры, группировку, даты, импорт и ошибки формата. Playwright проверяет браузерные сценарии и экран 390 px. По умолчанию используется `/usr/bin/chromium`. Другой бинарник можно передать через `CHROMIUM_PATH`; Chromium должен быть установлен. В CI сервер поднимается автоматически, локально допускается работающий Vite на порту 5173.

## Структура

- `src/App.jsx` — интерфейс и интерактивные компоненты.
- `src/styles.css` — оформление и адаптивность.
- `src/data/report.js` — чистые функции расчётов.
- `src/data/import-report.js` — чтение Excel без зависимости от стилей.
- `src/data/import.worker.js` — обработка импорта вне основного потока.
- `scripts/prepare-data.js` — подготовка встроенного набора.
- `tests/` — расчётные и браузерные проверки.

Приложение пока является frontend-прототипом: данные встроены в статическую сборку, серверного хранения, аккаунтов и подключения к API Ozon нет. Оно не опубликовано в интернете.
